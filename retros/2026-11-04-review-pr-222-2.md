**Deviations:** The TDD check did not apply because the PR has a justified `no tests:` (docs only), so no review worktree was created. The PR head was fetched into a review ref, and the ref was deleted at the end. `/code-review` ran at low effort and returned nothing, as expected for a prose diff. The real review was a manual check of the new rules against the D10 runners.
**Decisions not covered:** The skill does not say how to read an approval like "the rest, as the reviewer proposes" when that review offered alternatives and the agent picked one. I flagged it as a question for the person instead of treating it as approved.
**What the review found:** Blocker: the "who writes the root" rule (D4) has `red.sh` wrap the report and reject a file that has its own root. `red.sh` does not know which entry runs the bash helper, so implementing it as written would reject pytest, jest, vitest, go and cargo. To fix: a repeated id with an error could pass as a failure; recognizing a test file "by runner" when there is no runner field; the approval status contradicts the person's comment.
**Proposal:** In review-pr, when an ADR adds a rule that `red.sh` (or another shared tool) applies, check it against every D10 runner, not only against the runner the rule was written for. Rules written for one runner tend to leak into the others.
