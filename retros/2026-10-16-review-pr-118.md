**Desvíos:** el PR es de otro repo (la landing), así que no usé un worktree del checkout del orquestador: hice un clon temporal y traje `pull/3/head` a una ref propia, como pidió el orquestador. No corrí `agents_map.py`, `red.sh` ni el chequeo de labels porque la landing no tiene mapa, tests ni CI. Por eso la revisión fue a mano: extraje el texto visible de las 6 páginas para comparar los idiomas, armé un script de links y anclas, y comparé el texto contra los README de main.

**Decisiones no cubiertas:** la skill no dice cómo revisar un PR de un repo hermano sin AGENTS.md. Tampoco cómo comprobar el comportamiento de Vercel cuando las previews piden login y el CLI de Vercel no está instalado. Lo de `/es` sin barra final lo dejé como sugerencia: no lo pude probar en vivo.

**Lo que encontró la revisión:** un bloqueante y un "a corregir": los ids de los encabezados en /es/ perdieron las letras con tilde (`c-mo-contarlo`), y `/code-review` también lo vio. El botón "Copy" del instalador copia la sinopsis del README con `[--lang es] [--small] [--draft]` literal. En zsh falla con "bad pattern" y en bash `install.py` sale con el uso porque recibe 6 posicionales. La autoverificación del implementador (links, grep de nombres viejos) no lo podía ver: el texto es fiel al README, pero el comando no corre. Además, dos proyectos de Vercel despliegan el mismo repo, y por eso hay dos dominios en juego.

**Propuesta:** que review-pr pida, en las landings o docs con botones de copiar, pegar el comando copiado en un shell (o como mínimo pasarlo por `bash -n` y zsh) antes de dar el texto por bueno. Que la fidelidad al README no alcanza para lo que se copia y se pega quedaría como lección en `docs/agents/lessons.md`.
